# `\H` `child` argument

↑ **Parent:** [`\H` arguments](h-arguments.md)  
🏷️ **Tags:** [Disabled macro argument](disabled-macro-argument.md), [`Multiple` argument](multiple-argument.md)

This [`multiple` argument](multiple-argument.md) marks given IDs as being children of the current page.

The effect is the same as adding the [`\x` `child` argument](x-child-argument.md) argument to an under the header. Notably, such marked target IDs will show up on the autogenerated [tagged metadata section](tagged-metadata-section.md).

This argument is deprecated in favor of the [`\H` `tag` argument](h-tag-argument.md).

Example:
```
= Animal

== Mammal

=== Bat

=== Cat

== Wasp

== Flying animal
{child=bat}
{child=wasp}

\x[bat]

\x[wasp]
```
renders exactly as:
```
= Animal

== Mammal

=== Bat

=== Cat

== Wasp

== Flying animal

\x[bat]{child}

\x[wasp]{child}
```

The header `child` syntax is generally preferred because at some point while editing the content of the header, you might accidentally remove mentions to e.g. `\x[bat]{child}`, and then the relationship would be lost.

The [`\H` `tag` argument](h-tag-argument.md) does the same as the [`\x` `child` argument](x-child-argument.md) but in the opposite direction.
